# Wine App

A PWA for managing a personal wine inventory. Users scan barcodes to add and remove bottles across one or more Homes, with structured storage via Locations and Sections.

## Language

**Home**:
A shared wine storage space owned by one user. Members can be invited to access it.
_Avoid_: Cellar

**Location**:
A named storage unit within a Home (e.g. a wine rack, a fridge, a cabinet). One Location per Home is the default.
_Avoid_: Shelf, storage

**Section**:
A user-defined subdivision of a Location. In practice, mostly shelves.

**Stock**:
An inventory record tying a Wine (by barcode) to a Location and optional Section, with a quantity.
_Avoid_: Entry, inventory item

**Wine**:
Product information about a wine — name, type, region, grapes, etc. Cached from Vinmonopolet and keyed by Barcode.
_Avoid_: WineData, product

**Barcode**:
An EAN code that uniquely identifies a Wine. Used as the primary key for Wine and the foreign reference in Stock.
_Avoid_: EAN, product code

**Adjust**:
The operation of adding or removing bottles. Takes a signed delta — positive to add, negative to remove.
_Avoid_: Add/remove as separate operations

**Identify**:
The flow of discovering which Wine a label photo belongs to when the barcode is not already linked.

**Suggestion**:
A candidate Wine returned by Identify when no exact match is found. The user picks one to Link.

**Link**:
Permanently associating a Barcode with a Wine product code, so future scans resolve instantly without identifying.

**Member**:
Any user with access to a Home, including the Owner.

**Owner**:
The Member who created a Home. A role a Member can hold, not a separate entity.
_Avoid_: Admin (reserved for system-level administrators)

**Invitation**:
A token that allows someone to register a new account on the app. Generated by system administrators.
_Avoid_: HomeInvite, share token

**HomeInvite**:
A token that allows an existing user to join a specific Home. Generated by any Member.
_Avoid_: HomeShareToken, Invitation (which is reserved for system-level account creation)

## Relationships

- A **Home** has one or more **Locations**; one Location per Home is the default
- A **Location** has zero or more **Sections**
- A **Stock** record ties a **Wine** to a **Location**, optionally to a **Section**, with a quantity
- A **Home** has one or more **Members**; exactly one Member is the **Owner**
- **Adjust** creates or updates a **Stock** record
- **Identify** returns either a confirmed **Wine** or a list of **Suggestions**
- **Link** associates a **Barcode** with a **Wine**, resolving future scans instantly

## Example dialogue

> **Dev:** "When a user scans a barcode and Adjusts at a Location, does the Stock record belong to the Location or the Section?"
> **Domain expert:** "The Section if one is selected, otherwise the Location directly. A Wine can have Stock at both levels within the same Location."
>
> **Dev:** "If the barcode isn't recognised, do we Identify before we can Adjust?"
> **Domain expert:** "Yes — Identify (or Link) must happen first so the barcode resolves to a Wine. Once linked, future Adjusts go straight through."

## Flagged ambiguities

- "Cellar" was used throughout early documentation — resolved: canonical term is **Home**
- "Entry" was the code-level name for inventory records — resolved: canonical term is **Stock**
- "WineData" was the code-level name for wine product info — resolved: canonical term is **Wine**
- "HomeShareToken" was the code name for home membership invitations — resolved: canonical term is **HomeInvite**
